# Minecraft Java region files

Implemented by `format.minecraft-region` (`crates/saveprism-codecs/src/mca/`).

## Sources

- The public "Region file format" and "Anvil file format" pages on
  [minecraft.wiki](https://minecraft.wiki/w/Region_file_format). They describe the 8 KiB location
  and timestamp header, the 4 KiB sectors, the chunk length field, the compression byte and the
  external `.mcc` bit.
- The public "NBT format" page, already the source for `format.nbt`. Chunk payloads are Java
  big-endian NBT and are parsed by the same reader and writer.

An invented fixture (`fixtures/synthetic/minecraft-region/r.0.0.mca`) covers zlib, uncompressed,
gzip and an opaque compression type. It is generated by
`fixtures/tools/minecraft/make_region.py`.

## File layout

Big-endian throughout.

```
0x0000  1024 × location entry (3-byte sector offset, 1-byte sector count)
0x1000  1024 × timestamp (u32)
0x2000  sector 2, first chunk payload
        ...
```

An empty location has offset 0 and sector count 0. A non-empty location points at a 4 KiB sector;
the file must contain offset + count sectors. Chunks do not overlap. The header itself always
occupies sectors 0 and 1.

At the start of a chunk sector:

| Offset | Type | Meaning |
|---|---|---|
| `+0` | `u32` | payload length, including the compression byte |
| `+4` | `u8` | compression type |
| `+5` | bytes | compressed NBT |

Compression types 1 (gzip), 2 (zlib) and 3 (uncompressed) are decoded. Type 4 (LZ4) and unknown
types stay opaque. If the high bit of the compression byte is set, the payload lives in an external
`.mcc` file; the region only keeps the entry.

The chunk coordinates come from the region file name (`r.<x>.<z>.mca`) and the table index
(`local_x = index & 31`, `local_z = index >> 5`). The codec does not need the file name: it shows
the local coordinates from the index.

## Tree

The root is a read-only object (`MCA:region`) with one key:

| Path | Node | Editable |
|---|---|---|
| `/chunks` | `Array` (`MCA:chunks`), one object per non-empty location | no |
| `/chunks/n/index` | `Int` (`I32`), 0 to 1023 | no |
| `/chunks/n/x`, `/chunks/n/z` | `Int` (`I32`), local coordinates | no |
| `/chunks/n/timestamp` | `Int` (`I64`), the header timestamp | no |
| `/chunks/n/compression` | `Int` (`I32`), the original compression byte | no |
| `/chunks/n/external` | `Bool` | no |
| `/chunks/n/root_name` | `Str` | no |
| `/chunks/n/data` | NBT tree of an editable chunk | leaves |
| `/chunks/n/raw` | `Bytes`, compressed payload of an opaque chunk | no |
| `/chunks/n/note` | `Str`, why the chunk is opaque | no |

A chunk is opaque when it is external, uses LZ4 or an unknown compression type, or when its
decompressed bytes are not a complete NBT tree. An opaque chunk keeps its compressed bytes in
`raw`; the rest of the region remains editable. A damaged location table, an overlapping range or
a cut-short payload is refused instead of being guessed.

## Writing

The original file is the codec parameter `original`. An unchanged document returns it byte for
byte, including unused sectors, external entries and the timestamp table.

When a chunk's NBT tree changed, the writer encodes it again as Java big-endian NBT and compresses
it with the chunk's original scheme. If the new payload fits in the old sectors, it is written in
place and the rest of that range is zeroed. If it does not fit, it is appended at the next free
sector and the location entry is updated; the old sectors are left unused. Other chunks are copied
unchanged. Timestamps are read-only, so only the location table changes, and only for chunks whose
payload grew.

Limits: every decompressed chunk is read through the decoder budget. A region is not opened above
the input limit, and every NBT tree shares the document node limit. The full location table is
validated before any chunk is decoded.
