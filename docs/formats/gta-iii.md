# Grand Theft Auto III saves

Implemented by `format.gta-iii` (`crates/saveprism-codecs/src/gta3/`).

## Sources

- The public GTA III save description on GTAMods Wiki, `Saves_(GTA_3)`.
- The MIT-licensed 010 Editor template `formats/gta3save.bt` from
  [x87/GTA-Save-Formats](https://github.com/x87/GTA-Save-Formats), read for behaviour and block
  names.
- A public 100% complete PC save was used to confirm the offsets: the title `'LAST REQUESTS'`,
  island 2, in-game time 10:06, money 347,975, maximum wanted level 5 and maximum chaos 2,400 all
  read as plausible values. That save is not committed; the fixture is invented.

## File layout

Little-endian throughout. The classic PC file is always 201,820 bytes (`0x3145C`). It holds 22
blocks followed by a little-endian `u32` checksum.

Every block starts with a `u32` size that **does not** include the four size bytes, so the next
block starts at `block_start + 4 + size`.

| Blocks | Body |
|---|---|
| 0 | data starts immediately; no second size |
| 1 to 19 | a second `u32` size, then the data |
| 20, 21 | padding |

A classic PC save has exactly 22 blocks and their sizes walk to the checksum at `len - 4`. The
parser requires that exact end, so a wrong size or a cut-short file is refused.

### Block 0

Data starts at `block_start + 4`:

| Offset | Type | Meaning |
|---|---|---|
| `0x00` | `wchar_t[24]` | save name, NUL-terminated UTF-16LE |
| `0x44` | `u32` | current island (1 Portland, 2 Staunton, 3 Shoreside Vale) |
| `0x5C` | `u8` | in-game hour |
| `0x60` | `u8` | in-game minute |

### Block 1

The body starts at `block_start + 8` (after the top-level size and the nested size):

| Offset | Type | Meaning |
|---|---|---|
| `0x00` | `u32` | player count |
| `0x04` | `PlayerPed` | first player record, 1,530 bytes before the wanted values |

`PlayerPed` is `u32` unknown, `u16` unknown, `u32` ped reference, then a 0x5F0-byte CPed dump.
After that come the two wanted values, so they are at body offsets `0x5FE` and `0x602`:

| Offset | Type | Meaning |
|---|---|---|
| `0x5FE` | `u32` | maximum wanted level |
| `0x602` | `u32` | maximum chaos level |

Only the first player is read. The CPed body is kept opaque.

### Block 16

The body starts at `block_start + 8`:

| Offset | Type | Meaning |
|---|---|---|
| `0x00` | `u32` | money |
| `0x0F` | `u32` | money shown on screen |

### Checksum

The final four bytes are the wrapping sum of every preceding byte. Unlike GTA IV, the game
refuses a save whose checksum does not match. An unchanged document still writes the original
bytes exactly, including an already-wrong checksum. When an edit changes a value, the writer
recomputes the sum over the edited bytes.

## What is editable

| Path | Type | Meaning |
|---|---|---|
| `/game_time/hour` | `U8` | in-game hour |
| `/game_time/minute` | `U8` | in-game minute |
| `/player/money` | `U32` | money |
| `/player/money_on_screen` | `U32` | money shown on screen |
| `/max_wanted_level` | `U32` | maximum wanted level |
| `/max_chaos` | `U32` | maximum chaos level |

The title and current island are read-only. The writer never changes the file length, so block
sizes stay valid.

## Limits and open questions

- Only the classic PC save is handled. Mobile and Definitive Edition saves use different layouts
  and are refused.
- Health, armour, weapons, garages, vehicles, stats and mission state are not decoded. They stay
  byte-for-byte.
- The CPed dump is 0x5F0 bytes and is not interpreted.
- Vice City has its own container and is not handled here. San Andreas has `format.gta-sa`, GTA IV
  has `format.gta-iv`, and GTA V / Red Dead Redemption 2 use a RAGE container with an AES-ECB body
  and a key stored in the game executable.
